VERDICT: AGREE-WITH-CAVEATS

1. Yes, for the default in-admin Drupal edit primitive, the write is established as MCP-module based. `drupal_node_update` calls `callDrupalMcp(..., mcp_update_content, ...)`, and `callDrupalMcp` hardcodes `/_mcp_tools` then performs MCP `client.callTool`. Same pattern holds for create/publish in code: [handlers.ts](/Users/ordnas/Code/cinatra-ai/drupal-mcp-connector/src/mcp/handlers.ts:335), [drupal-mcp-client.ts](/Users/ordnas/Code/cinatra-ai/drupal-mcp-connector/src/lib/drupal-mcp-client.ts:14).

   Caveat: the live wire proof only shows the `mcp_update_content` update case. Create-draft and publish are code-proven, not live-proven by that capture. Also “no direct REST write anywhere” is too broad; say “no direct REST/JSON:API content write in the active/default in-admin Drupal primitive path reviewed and captured.”

2. The read-hop claim is fair, but it should be framed as a hybrid path: direct JSON:API `GET` is used for the pre-edit diff read when available, while mutations go through the Drupal MCP module. This does not undercut the `(a)` verdict for writes, but it does undercut any blanket claim that “Cinatra reaches Drupal only through MCP.” Also, “read-only” describes the operation/code path, not necessarily the bearer’s theoretical capability.

3. I do not see an internal flag that makes `drupal_node_update` switch to JSON:API writes. But `DRUPAL_CONTENT_EDITOR_A2A_URL` is more than harmless plumbing: if pointed at a different compatible agent service, that agent could implement writes however it wants. So the proof should be scoped to the stock/default `@cinatra-ai/drupal-agent` and declared connector primitives. One more unrelated caveat: `drupal_node_create_draft_revision` looks semantically suspicious, because the handler calls `mcp_create_content` with `status:false` and no existing `nodeId`; that is still MCP, but “draft revision” may be overstated.

4. The WordPress contrast is basically correct, as long as you phrase it as the leaf CMS hop. Both widgets go through Cinatra/agent/connector machinery first. The difference is that WordPress’s content-editor write ultimately calls WP REST `POST /wp/v2/posts|pages/{id}` with Basic/Application Password auth, while Drupal’s content-editor write ultimately calls Drupal `/_mcp_tools` MCP tools. See WP update path: [wordpress-client.ts](/Users/ordnas/Code/cinatra-ai/wordpress-mcp-connector/src/lib/wordpress-client.ts:1489).
